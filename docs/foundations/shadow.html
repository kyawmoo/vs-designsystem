Foundations // Shadow

Shadow

Flat design — no box-shadow anywhere, on either product. Elevation comes only from a 1px border and background-color contrast.

Why

Decided with Master KMO: "Let's fuse flat design." A single token, --vs-shadow-none, exists so any lingering box-shadow in either codebase has an explicit, intentional value to be set to — rather than being silently removed with nothing marking the decision.

Not yet fully live on either site. vectorsticker.com's card-v, widget and modal styles still carry shadows in production CSS — out of scope for a change made from this repo (it's the main production site). On reports.vectorsticker.com, every exported design- system component (Card, SummaryCard, TableWidget, FilterBar, Tabs) is already shadow-free — but auditing src/index.css directly found a few bespoke, non-component styles that still use a real shadow on purpose: a floating score tooltip, scatter-plot marker "bubbles" on the Opportunities view, and a subtle hover-lift on list items. These are deliberate depth cues on specific interactive elements, not leftover defaults, so removing them is a real design call (would they still read correctly as floating/interactive with only a border?) rather than a mechanical swap — flagged for Master KMO to decide rather than stripped silently.
