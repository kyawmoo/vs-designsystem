02 // Composition

Built from Tabs

The header's tab switcher is the same <Tabs> pattern documented separately.

TableWidget's optional header-right tab switcher renders the exact same vs-segment-control / vs-segment-button markup as the standalone <Tabs> component documented on its own page — this is in fact where that pattern was first formalized from. A future pass could have TableWidget render <Tabs> internally instead of duplicating the markup; left as-is here since it works correctly today and that refactor carries its own regression risk on an already-live component.

03 // Platform

React only — no Blade wrapper

Admin tables use a vendored JS plugin, not a presentational CSS pattern.

The main site's admin panel tables are built on the vendored datatables.min.css / DataTables jQuery plugin — sorting, pagination, and search are all driven by its own JS initialization per page, not a shared CSS class this system could thin-wrap the way vs-pagination.blade.php wraps Laravel's paginator. Re-implementing that JS behavior as a design-system component would be a new feature, not a presentational wrapper, so it's deliberately out of scope here — same reasoning as excluding the item price/cart logic from vs-card.blade.php. Revisit only if Master KMO asks for it explicitly.
