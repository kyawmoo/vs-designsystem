How the width is worked out (All Items page, items/index.blade.php): the page container is .container-custom — 1450px wide from 1600px up (app.css), otherwise Bootstrap 5.3's 1320 / 1140 / 960 / 720 / 540px — minus 12px padding each side. The grid is row g-3 (16px gutter) with row-cols-md-2 row-cols-xxl-4 (search-items.blade.php). Example at ≥1600px: (1450 − 24 + 16) ÷ 4 − 16 = 344.5px. The image is square because custom.css sets aspect-ratio: 1 / 1 on .item-img. Other live values in this replica: no border, 8px radius, 24px body padding, 16px / 500 title, 18px / 600 price, edge-ribbon badge (top 25px, 10px 12px padding, 12px uppercase), 50px-tall btn-md btn-padding icon buttons, Montserrat 13px body text (custom.css).

10 // Platform Difference

Generic Card: React vs. Blade

Same name, different default border.

No border — real .card-v on the public site.

.card-v, app.css

Blog post card

variant="blog" — extra padding, adds a border.

Blade card-blogblog

.card-v.card-blog

The real .card-v class (public/themes/basic/assets/css/app.css) has no border — it sits on the public site's white page background, so padding and radius alone read as a card. The dashboard's cards (SummaryCard, TableWidget) always use a 1px border because they sit on the report site's gray canvas. React's <Card> follows that dashboard convention; Blade's <x-vs-card> wraps the real class as-is.
