11 // Ergonomics & Governance

Do’s and Don’ts

Hierarchy guidelines.

Do Single clear intent

Use only one primary button per view.

Don’t Competing focus

Don’t repeat primary emphasis — it kills the hierarchy.

Do Contextual anchoring

Vector_Spec.svg

Icon-only buttons need context — place them where their function is obvious, and always give them an aria-label.

Don’t Mystery-meat navigation

Don’t strand icon-only buttons without context — users can’t tell what they do.

Usage — React

import { Button } from '@vectorsticker/design-system'; <Button emphasis="primary">Save changes</Button> <Button emphasis="tertiary" size="sm">Cancel</Button> <Button iconOnly icon={<Trash2 />} aria-label="Delete" />

Usage — Blade

<x-vs-button variant="primary">Save changes</x-vs-button> <x-vs-button variant="tertiary" size="sm">Cancel</x-vs-button> <x-vs-button variant="tertiary" icon-only aria-label="Delete"> <x-slot:icon><i class="fa-solid fa-trash"></i></x-slot:icon> </x-vs-button>

Rollout status: the React Button follows spec v2. The Blade component still renders vectorsticker.com's own .btn styles (opacity hover, 6px radius) until that site's CSS is updated — a separate change on the main site.
