Animation & Effects // Reveal

Reveal

The page-opening animation: a dark curtain grows from the top-left corner, then the side menu slides in from the left and the body fades in. Plain CSS rules in react/src/styles.css and blade/components.css (the same block, kept equal by check-tokens), timed by the --vs-motion-* tokens. No JavaScript is needed for the effect.

Demo

The demo is a page of its own shown in a frame, so the curtain covers the frame and not these docs. Press Replay to see it again.

Usage: plain HTML / Blade

<!-- first thing inside <body>: one curtain per page --> <div class="vs-reveal-curtain" aria-hidden="true"></div> <aside data-vs-reveal="slide-left">…</aside> <main data-vs-reveal="fade">…</main>

The attribute goes on the element itself, not on a wrapper, so sticky and flex layouts keep working. The React and Blade components that write this markup for you are below.

Usage: React

import { Reveal, RevealItem } from '@vectorsticker/design-system'; <Reveal> <RevealItem as="aside" variant="slide-left">…</RevealItem> <RevealItem as="main" variant="fade">…</RevealItem> </Reveal>
ComponentPropValues
RevealplayDefault: true for the first Reveal of the page load, false for any later one, so signing out and in again does not replay the opening. Pass true or false to decide yourself. Read once, when it mounts.
RevealItemvariantslide-left · fade (default) · rise
RevealItemasThe element to render, default div (aside, main, header, …). The item is this element, not a wrapper around it. A component of your own also works if it puts the extra props (data-vs-reveal, className) on its root element.
RevealItemothersPassed to the element (className, id, role, …).

Reveal renders no wrapper element: it adds the curtain (a fixed layer, aria-hidden) next to its children. Use one per page, around the page shell. With play off, or on a later mount, there is no curtain and the items carry no attribute, so everything is shown at once. The jsdom unit tests check this markup; how it looks and moves is checked in real browsers by npm run test:browser (in react/).

Usage: Blade

<x-vs-reveal> <x-vs-reveal-item as="aside" variant="slide-left">…</x-vs-reveal-item> <x-vs-reveal-item as="main" variant="fade">…</x-vs-reveal-item> </x-vs-reveal>
ComponentPropValues
x-vs-revealplayDefault true. :play="false" renders the content with no curtain and the items inside stay still. A page opts in by using the component; nothing animates on a page that does not.
x-vs-reveal-itemvariantslide-left · fade (default) · rise. Any other value falls back to fade.
x-vs-reveal-itemasdiv (default), aside, main, header, footer, section, nav, article, ul, ol, li, p, span. Any other value falls back to div, so a tag name cannot be injected. The item is this element, not a wrapper.
x-vs-reveal-itemothersPassed to the element (class, id, aria-*).

The Blade page renders on the server for every page load, so there is no "once per session" memory: the opening plays each time a page that uses x-vs-reveal is opened. Put it only on the pages that should open this way. The curtain markup is the same as in React. The CSS is the vs-reveal block in blade/components.css; the host page must load that file.

Variants

data-vs-revealWhat it doesTiming (tokens)
slide-leftSlides in from the left edge of its own box. For the side menu.Starts when the curtain ends. --vs-motion-duration-enter, --vs-motion-ease-decelerate
fadeFades in. For the page body.Starts --vs-motion-delay-body after the curtain. --vs-motion-duration-enter, --vs-motion-ease-standard
riseFades in and rises --vs-motion-rise-distance. For a header or a card.Same as fade

The curtain itself takes --vs-motion-duration-curtain with --vs-motion-ease-standard; its colour is --vs-color-brand-secondary.

Rules

  • Content is never hidden by a base rule. The hidden state exists only inside the keyframes, so if the animation is switched off (reduced motion, even while it runs) the content is simply visible. A opacity: 0 in a normal rule would stay hidden for good in that case.
  • No double fade. An element with data-vs-reveal inside another one does not animate by itself.
  • One curtain per page. It is fixed to the screen and does not take clicks (pointer-events: none), so scrolling and clicking work during the opening and the scroll position does not matter. After the animation it is hidden (visibility: hidden).
  • Plays once per page load. A CSS animation plays once for an element. It plays again if that element is inserted or replaced later, or hidden with display: none and shown again. React: Reveal owns this. It knows when the opening is over (the time is read from the tokens: curtain + body delay + the longest entrance or title + a little room) and an item or title that mounts after that renders plain, with no attribute and no letters, so a view shown again after another tab, or a list re-rendered, never replays, and the app needs no guard of its own. An element that mounts during the opening still plays; one that was already there is not changed when the opening ends. Reduced motion counts the opening as over at once. Blade / plain HTML: there is no component state; the opening plays on each page load, and an element inserted later (a Livewire re-render) animates again, so put data-vs-reveal on the page shell, not inside re-rendered lists.
  • Keyboard. The waiting state of an entrance is also visibility: hidden (only in the first keyframe, so it is visible again as soon as the entrance starts): content that is not shown yet cannot take keyboard focus, and it is not read by a screen reader until it appears. Measured: with the curtain up, Tab no longer lands on a link inside the body (before, it did, invisibly).
  • Reduced motion. With prefers-reduced-motion: reduce the curtain is not shown and nothing animates. This also works when the setting is switched while the animation runs. If it is switched back, the animation starts again from the beginning.
  • JavaScript off. The effect is plain CSS, so it still runs and the page is shown at the end.

Performance: do not put the main content of a page that is judged on loading speed inside the Reveal

The content of a data-vs-reveal element is not visible for about 1.2 seconds (the curtain and the body delay). The browser counts the largest piece of content only when it is visible, so if the largest heading or image of a page is inside a revealed element, the Largest Contentful Paint (LCP) is that late. Measured in Chromium (headless, 390px wide, no throttling, 5 runs each, a page whose largest content is a heading): without the Reveal 20 to 40 ms; with the heading inside a data-vs-reveal="fade" element 1924 to 1936 ms. A real phone on a slow network will differ; the 1.2 s wait is added on top.

  • Pages behind a login (a dashboard): loading speed is not judged by search engines, and the opening is part of the product: fine.
  • Public pages that are ranked or paid for by speed (a shop, a blog): reveal only the page chrome (side menu, header, cards below the first screen) and leave the hero heading and the hero image outside any data-vs-reveal element. Do not wrap the whole page in a revealed element.
  • Measure the page with and without it before turning it on (Lighthouse, or the browser's LCP in the Performance panel).

Accessibility

The curtain is decoration (aria-hidden="true") and takes no focus or clicks. The animated elements keep their normal role, order and text: nothing is split into letters except in RevealText, which keeps one real copy for screen readers. Only transform, opacity and the curtain mask are animated, so the layout does not shift. The animation runs about two seconds in total (--vs-motion-duration-curtain + --vs-motion-delay-body + --vs-motion-duration-enter = 1.9 s with the default tokens), is not triggered by the visitor, and is switched off by reduced motion.

Browsers

The curtain needs @property (Chrome 85, Safari 16.4, Firefox 128). Without it the hole jumps open halfway through instead of growing, and the page is still shown at the end. Where hypot() exists the hole ends exactly at the screen diagonal; elsewhere it ends at 150vmax. Tested so far in Chromium only; WebKit and Firefox are covered by the browser check that comes in the next change.
